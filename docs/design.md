# 设计说明

MoonRoster 用于为小规模课程和资源活动安排时间与场地。项目负责把教师、班级、教室、容量和可用时段组合成可检查的安排，适合课表编制、实验室活动和小团队会议安排。

## 约束

- 同一时段内，同一教师、班级或教室不能被多个课程占用。
- 教室容量不能小于课程人数；课程只能安排在允许的时段。
- 已锁定的时间或教室必须保留。
- 搜索找到合法方案时返回方案；完整搜索后没有方案时才报告无解。达到搜索预算时返回未知，不能推断无解。

第一版使用离散时段，每项课程占用一个时段和一个教室。连续多时段、跨周规则、日历导入、多人协作和自动确定全局最优不属于第一版范围。

## 取舍与验证

确定性搜索可以让同一份输入便于复现。验证应包含可手算案例、违反每类约束的案例、锁定冲突、重复标识以及搜索预算耗尽。对于小规模问题，使用独立枚举与结果核对，避免只让求解器验证自身的输出。

项目方向由维护者选定；开发过程中使用 AI 辅助实现和检查，代码、测试和结果均应可以独立阅读和复现。

## 资源不足预检

正式搜索前，将候选安排分别投影为三类二分图：每位教师的课程与时段、每个班级的课程与时段、全部课程与“时段×场地”位置。用增广路径检查能否为所有课程找到不同资源，能够识别“总资源看似足够，但某个课程子集挤在过少资源里”的矛盾。例如三门同教师课程都只能选两个时段，即使输入还有其他不可用时段，也能在搜索前证明无解。

这三个检查都是原问题的放松，只提供必要条件；任一匹配失败可安全返回无解，全部成功仍需执行完整约束搜索。它们不能代替求解器，也不能承诺任意输入都能快速完成。诊断按课程输入顺序选择教师和班级，保持复现稳定。

匹配算法与独立穷举比较全部 512 种三对三边关系；端到端测试覆盖教师、班级、场地的子集不足及增加可用时段后的恢复，同时覆盖各个放松均通过但整体仍无解的案例。64 门课程的固定案例验证预算恰好完成和单教师仅有 63 个可用时段时零搜索节点诊断。
