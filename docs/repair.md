# 多资源计划修复

在已有安排上处理变化。调用者列出每项任务的原方案、允许的替代方案和改动成本。搜索只在这些候选内找解，保持冻结任务，并检查跨时段容量与前置关系。

## 接口

MoonBit 包为 `2515050242/moonroster/repair`。以 `@repair.solve(problem)` 取得带状态的结果，用 `@repair.audit(problem, choices)` 独立核对任意完整方案。[可执行的 MoonBit 用法](../repair/README.mbt.md)和[公开类型](../repair/pkg.generated.mbti)。

JSON 输入字段均必填：

| 字段 | 含义 |
| --- | --- |
| `horizon` | 整数时间轴长度，1–128 |
| `budget` | 至多尝试的分支候选数，1–100000，预处理不计入 |
| `resources` | 最多 32 个唯一命名资源。每个资源有 `id` 和长度等于 horizon 的 `capacity` 数组。0 表示该刻不可用 |
| `tasks` | 最多 64 项。每项有唯一 `id`、`options`、`baseline`、`frozen`、`change_cost` 和 `after` |
| `options` | 每任务 1–64 个候选。每项含 `start`、`end`、`demands`，占用半开区间 [start, end)。需求为 `resource` 和正整数 `units`，同一选项中资源不得重复。可用空需求表达纯依赖任务 |
| `baseline` / `frozen` | 原候选的零基索引。冻结时必须选原候选，即使资源变化让它无解 |
| `change_cost` / `after` | 改离原候选付一次正整数成本。after 是前置任务 ID 数组，前置结束须不晚于本任务开始 |

资源容量和改动成本上限为 100000。输入的时间单位由调用者统一指定。计划文件上限 262144 个 UTF-16 码元，JSON 嵌套上限 16。所有候选由调用者给出。没有自动生成候选、拆分任务、持续执行调度或最优运行时间保证。

## 搜索与复核

按候选数从少到多分支，同数按输入顺序。每个任务先尝试原方案。分支检查已分配任务的依赖和逐刻累计容量。改动成本非负，且部分任务原方案在当前容量下已不可用，据此得到下界并剪去不可能改善当前方案的分支。没有找到方案且穷尽所有分支时返回 `unsatisfiable`。

| JSON 状态 | 含义 | CLI 退出码 |
| --- | --- | --- |
| `optimal` | 已证明给定候选中总改动成本最低 | 0 |
| `feasible` | 预算已耗尽，保留可行方案，最优性待证 | 0 |
| `unknown` | 预算已耗尽，尚未找到可行方案 | 3 |
| `unsatisfiable` | 给定候选无解 | 1 |
| `invalid` | 输入或引用无效 | 2 |

有方案时返回 `choices`、`cost`、`lower_bound`、`attempts` 和逐任务 `changes`。choices 按任务输入顺序排列。已证最优时 JSON 下界等于方案成本。预算中断时下界来自单任务不可保留原方案的成本总和，可能较松。返回首个同成本方案。

使用 `--audit PROBLEM.json CHOICES.json` 检查外部方案。第二个文件可以是索引数组或包含 `choices` 的求解结果。校验器重新计算成本和总占用，忽略文件自报的成本或状态，发现冲突时返回首个见证。校验通过为 `ok`，退出码 0；冲突为 `conflict`，退出码 1；格式错误为 `invalid`，退出码 2。校验只判可行，不证明最优。

## 三个可复现的变更

| 场景 | 改动触发与约束 | 预期修复 |
| --- | --- | --- |
| [实验设备](../examples/repair/equipment.json) | 主设备前两刻停机。校准任务冻结，样本分析同时需要设备与操作员 | 校准保留，分析换到备用设备并改到后两刻，成本 3 |
| [软件发布](../examples/repair/release.json) | 部署安排早于构建结束，构建冻结并占用两单位执行器，部署需执行器及审批资源 | 部署推迟到构建完成，通知继续按原计划，成本 4 |
| [物流码头](../examples/repair/dispatch.json) | 两笔订单争用一个码头，优先订单改动代价较高 | 改常规订单，保留优先订单，成本 2 |

例子是合成夹具。CLI 回归检查三例的具体索引和成本。库测试将 64 个小问题的搜索结果与枚举全部候选并调用校验器的结果比较，还检查预算中断和方案冲突。
