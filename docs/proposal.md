# 星序 Xingxu 项目说明

本文件是依据源码与合成示例整理的技术资料，供维护者核对并人工撰写报名材料。

## 定位与交付

星序面向排程系统开发者，提供独立的 MoonBit 多资源计划修复库 `2515050242/moonroster/repair`，带类型接口、JSON 接口、命令行和外部方案校验器。原有课程网页是仓库早期应用。许可证为 Apache-2.0。

## 定义

调用者提供一组任务，每项任务包含原候选、可用替代区间、资源用量、前置任务与改动成本。资源容量可以随离散时间变化。为每项任务选一个候选，冻结任务保留原候选，前置任务须先完成，逐刻资源用量须在容量内。偏离原候选的任务计一次改动成本，总和是搜索目标。候选由调用方提供。

输出按任务顺序排列的候选索引、成本、变更清单与搜索结论。完整搜索可以证明最优或无解。预算耗尽时，保留可行方案并报告最优性待证，或报告结果未知。独立校验器重新计算占用与成本，发现问题时提供任务或容量冲突见证。

## 完整示例

码头只有一个泊位。两单原定占用 [0,1)，因此第 0 刻需求 2 超过容量 1。常规订单可改到 [1,2)，成本 2。优先订单可改到 [2,3)，成本 9。两单都改成本 11。求解结果 choices=[1,0]，即只调整常规订单，最低成本为 2。每项任务的候选索引从 0 开始。

```sh
moon build cmd/web --target js --release
node cmd/solve.mjs --repair examples/repair/dispatch.json
```

结果的 status 为 optimal，choices 为 [1,0]，cost 为 2。输入、校验命令和完整 JSON 输出见 README。另有设备停机时替代设备、软件发布时前置顺序修复两组合成示例，预期改动成本分别为 3、4。

## 证据与边界

三个目标各有 33 项测试，修复测试含 64 个小实例的枚举对照。verify_examples.mbtx 核对三组修复夹具的方案与成本，以及码头原方案的容量冲突。场景输入是合成数据，实际应用情况由维护者如实补充。

多资源预约和约束排程有既有库实现。星序集中表达原计划、冻结项、加权改动目标及结构化变更，独立维护该候选模型。搜索规模受候选组合影响。来源和同类能力见 [相关项目](related-work.md)，接口及限制见 [修复库文档](repair.md)。开发使用 AI 辅助实现与验证。
