# 复审核对

驳回通知指向小规模课程与共享场地的具体应用定位，认为场景、功能和通用性过窄。通知允许在 2026 年 11 月 30 日前修改报名表提交最新信息。以下为本地改动事实和人工改写申报书时可核对的证据。

| 驳回点 | 本地改动 | 如何核对 |
| --- | --- | --- |
| 场景集中在课程与场地 | 同一修复 API 处理实验设备停机、发布任务依赖、物流码头争用。分别覆盖资源替代、前置顺序、优先保留高代价任务 | [三例输入和预期结果](repair.md#三个可复现的变更) |
| 功能停留在生成一份排程 | 新增基线对照、冻结、按改动成本选择方案、预算结果区分、变更清单和外部方案校验 | README 中的修复与校验命令 |
| 通用性窄 | 资源、容量曲线、备选区间和任务依赖由调用者定义，可直接从另一个 MoonBit 包调用 | [公开接口](../repair/pkg.generated.mbti)及[编译执行的调用示例](../repair/README.mbt.md) |

改写申报书时，可以围绕“设备坏了或任务延期，怎么修好原计划并尽量少改”说明动机。以码头例解释，若只选第一个可行方案，可能移动优先订单；权重 2 与 9 表达两种改动的相对代价，库会复核约束并搜索较低成本。旧课表网页可列为兼容应用。将三类修复示例、对照库和算法边界写入正文，明确数据是合成夹具。实际使用或本人验证情况请按事实填写。

本地实现使用候选区间离散模型，适合受限范围的计划修复。复杂度仍随候选组合增长，预算中断只返回已证实的信息。同类库已经覆盖预约和通用排程，本轮差异在基线稳定性目标和可复核变更清单。最终立项判断由组委会作出。[同类项目核对](related-work.md)
